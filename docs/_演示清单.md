### 推荐页最值得演的两手

1. **健康目标 + 三套对比**：点「控糖」→ 两个热量框自动变 400 / 600，页面出现
   「套 400–600 kcal 并排掉甜味（库里标了「甜」的 5 道）」，紧接着一行
   「⚠ 这里只有甜味标签，没有糖分数据 —— 咸味菜里的隐形糖判不出来，糖尿病人请以店家与医生为准。」
   → 点「一次看三套」→ **省钱 / 均衡 / 吃饱** 三张卡分别是 `¥22 / 650 kcal / 93%`、
   `¥77 / 675 kcal / 96%`、`¥79 / 700 kcal / 100%`。
2. **不填热量区间时点三套**：三张卡会一模一样，界面会自动出现一句解释
   「这次三套算出来是一样的 —— 三种策略的差别全在「热量目标」上」，
   并给一颗「用「正常 500–700」再比」的按钮。**这是诚实的降级提示，不是按钮坏了。**

## 三、三个核心卖点（老师大概会问）

1. **预算 + 热量 + 过敏原三重约束下的组合推荐**
   不是罗列菜品，是在预算内挑出「够吃、不超热量、避开你的过敏原」的一整套。
   **热量是目标不是天花板**：填 400–800 时，改前只能凑到 41%，现在能到 84–100%。
2. **跨地区比价**
   同一道菜（同食材 + 同形态）在七个地区的价格摆在一起，按人民币折算排序，并标出「口味不同」的那些；
   超过 20 条时明说「只显示最便宜 20 条」。
3. **餐后评级把「吃了什么」变成分数**
   预算达成、热量达成、口味匹配三项算分，出「顶级/优秀/…」档位；作废单不计入图鉴与勋章。

## 五、出问题时的兜底

### 如果模拟器白屏 / 页面数据是旧的

**九成是开发者工具的编译缓存**（踩过两次：首页徽章显示错乱、计划页看不到新加的控件；
源码和 dist 都是对的，最后查出是工具缓存里存着旧的编译结果）。

**顺序很重要 —— 必须先杀进程再清缓存**（先清后杀的话，进程退出时会把缓存写回去）：

1. 完全退出开发者工具。普通权限杀不掉，要提权：
   `taskkill /F /IM "微信开发者工具.exe" /T`（进程名是中文，`wechatdevtools.exe` 匹配不到）。
2. 确认进程数归零后，删掉这两处缓存**里面的东西**（不要删目录本身）：
   ```
   C:\Users\ROG\AppData\Local\微信开发者工具\User Data\721eda894475a9e096fa66a5dc5841ae\WeappCache\WeappCompileCache
   C:\Users\ROG\AppData\Local\微信开发者工具\User Data\533feed88e32fb3e0a6efff8dd187ff1\WeappCache\WeappCompileCache
   ```
3. 重新打开工具，等它重新编译一遍（大约 30 秒）。

### 如果后端没起来 / 所有页面都是空的

重新跑第一节第 1 步，确认那个窗口还开着。`http://127.0.0.1:13000/api/world/meta` 打不开就是后端没了。

### 如果有网络版（H5）可以应急

后端已经开了跨域（`Access-Control-Allow-Origin: *`），所以浏览器里也能跑：

```powershell
cd D:\ai\工作区\dsh\小组作业\Sushi_House\_h5run
npm run dev:h5
```

然后浏览器开它提示的地址。**这条是备用路线**，界面会略有差异（比如没有小程序的原生导航栏）。
