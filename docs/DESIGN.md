# 寿司朗点餐测评系统 · 设计文档 v1

> 优化预算、判断口味，以最低的成本得到良好的用餐体验。

## 1. 产品定位

一个以「寿司朗 / 寿司郎」菜单为背景的**个人用餐规划与测评**小程序：
餐前根据预算、热量和口味偏好推荐菜品组合；餐后通过照片 / 账单 OCR / 手动录入记账，
系统生成五档趣味评级，并通过**寿司图鉴 + 勋章**驱动复购。

## 2. 功能范围（第一版）

### 2.1 账号与个人设置
- 用户名 + 密码注册 / 登录 / 退出；密码仅存哈希（scrypt，盐随哈希一起存）。
- 基于服务端会话令牌（`sessions` 存令牌 SHA-256 + 过期时间）鉴权。
- 修改昵称、头像；编辑**口味偏好**与**忌口**。
- 偏好分四类：`喜欢 / 不喜欢 / 忌口 / 过敏`。
- 数据隔离：用户只能访问自己的计划、照片、记录。

### 2.2 菜单与新品预告
- 浏览、搜索、按分类筛选菜品；查看价格、每份热量、食材 / 口味标签。
- 菜品状态：`待上架 pending` / `在售 on_sale` / `已下架 off_sale`。
- 待上架展示预计日期；在售参与推荐；已下架仍可在历史记录中查看。

### 2.3 餐前推荐
- 输入单人预算（必填）和可选热量上限，输出「份数 + 预计总价 + 预计总热量」。
- 规则：
  1. 先排除与「忌口 / 过敏」标签冲突的菜品；
  2. 按「喜欢」标签加权、按「不喜欢」降权排序；
  3. 设置热量上限时，仅使用已录入热量的菜品；
  4. 组合尽量贴近预算且不超热量；
  5. 找不到可行组合时提示调整条件。
- 计划落库：`meal_plans` + `meal_plan_items`（保存菜名 / 单价 / 热量的生成时快照）。

### 2.4 餐后记录与识别
- 三种录入方式：餐品照片估价、账单照片 OCR、手动录入。
- 识别结果先作为**草稿**，用户可改菜品、份数、单价、实付金额。
- 分开显示「按菜单价估算金额」与「账单实付金额」，热量按确认菜品 × 份数估算。
- v1 说明：OCR / 照片估价为**模拟识别**（返回可编辑草稿），预留真实 OCR / 视觉接口位。

### 2.5 用餐测评与历史
- 用户自评 1–5 星 + 短评。
- 系统独立生成五档趣味评级：`夯 / 顶级 / 人上人 / NPC / 拉完了`。
- 评级依据：预算达成、热量目标达成、口味偏好匹配（规则版本 `v1`）。
- 历史可查看推荐方案、实付金额、热量估算、评级依据。

### 2.6 寿司图鉴与勋章
- 首次确认吃过某菜 → 解锁图鉴，并发放「首尝」勋章。
- 同一餐吃 3 份：图鉴记 **1 次、3 份**。
- 里程碑勋章按累计次数发放（如「天妇罗达人」= 天妇罗标签累计 15 次）。
- 草稿、作废记录、未匹配到菜单的菜品**不计入**进度。

### 2.7 管理员维护
- 维护分类、菜品（价格 / 热量 / 标签 / 上下架 / 预告）、标签、勋章门槛。
- 第一版按单人用餐、单套菜单设计。

## 3. 评分与勋章规则（v1）

### 3.1 五档评级
系统评分（0–100）：

| 维度 | 规则 |
|---|---|
| 基础分 | 60 |
| 预算达成 | 实付 ≤ 预算 `+15`；超预算且超支越多扣分越多（最低 `-15`） |
| 热量目标 | 有上限且达标 `+15`；超标按比例扣分（最低 `-15`） |
| 口味匹配 | 喜爱标签命中率 × 20 |
| 不喜欢命中 | 每个 `-3` |

档位映射：`≥90 夯`、`≥75 顶级`、`≥60 人上人`、`≥40 NPC`、`<40 拉完了`。
规则版本号写入 `meal_evaluations.rule_version`。

### 3.2 勋章
- **解锁勋章**：每道菜一条 `unlock` 规则，首次确认即得 `{菜名}首尝勋章`。
- **里程碑勋章**：按菜品或标签累计「确认次数」达标发放（如「天妇罗达人」= `tag=油炸`，15 次）。

## 4. 技术架构

| 层 | 选型 |
|---|---|
| 前端 | Uni-app + Vue3（HBuilderX 开发，编译微信小程序 / H5） |
| 后端 | Node.js 零依赖（内置 `http` + 内置 `node:sqlite`），REST API，内置静态托管上传图片 |
| 数据库 | SQLite，文件 `database/sushi_house.db` |
| 鉴权 | 服务端随机令牌，`sessions` 存 `sha256(token)` 与过期时间 |

## 5. 数据字典

### 5.1 账号与偏好
- `users`：账号、密码哈希、昵称、头像、角色、状态。
- `sessions`：用户、令牌哈希、过期时间。
- `user_preferences`：用户对各标签的 `like / dislike / avoid / allergy` 偏好。

### 5.2 菜单与标签
- `dish_categories`：分类名、排序、状态。
- `dishes`：分类、菜名、图片、价格、每份热量（可空）、状态、预计上架日期。
- `tags`：标签名、类型（`ingredient` 食材 / `flavor` 口味）。
- `dish_tags`：菜品 ↔ 标签关系。

### 5.3 餐前计划
- `meal_plans`：用户、预算、热量上限、生成时偏好快照、预计总价 / 总热量。
- `meal_plan_items`：计划、菜品、份数、生成时菜名 / 单价 / 热量快照。

### 5.4 餐后记录
- `meals`：用户、关联计划、用餐时间、实付、星级、短评、确认状态（`draft / confirmed / void`）。
- `meal_items`：餐记录、菜品、份数、单价、热量、录入来源（`photo / ocr / manual`）。

### 5.5 照片与测评
- `meal_uploads`：图片存储位置、类型（`dish / bill`）、识别状态与结果。
- `meal_evaluations`：估价、估算热量、分数、档位、评级依据、规则版本。

### 5.6 图鉴与勋章
- `badge_rules`：类型（`unlock / milestone`）、目标菜品或标签、所需次数、名称、图标、描述。
- `user_badges`：用户获得的勋章及时间。
- `user_dish_progress`：用户对每道菜「吃过几次 / 共几份 / 首次何时」，从已确认记录统计。

- 已完成：账号、菜单、推荐、餐后记录、评级、图鉴勋章、管理员维护（API）。
- v1 模拟：账单 OCR、照片估价（可编辑草稿，接入真实服务即可替换）。
